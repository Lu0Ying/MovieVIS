| D7 | 讨论热度 | 评论数、点赞数 | 气泡大小、代表评论排序 |

### 1.5 爬取路线：可行性、边界与风险

已核实的技术事实：

- 短评列表页为 `https://movie.douban.com/subject/{subject_id}/comments?start=0&limit=20&status=P&sort=new_score`。
- 实际接口常见为 `/j/movie/{id}/comments`，需要 `start`、`limit`、`status`、`sort` 参数，并依赖 `ck`（CSRF Token）与设备标识等 Cookie；缺失会 403 或空数据。
- 豆瓣 `robots.txt` 未禁止 `/subject/` 路径，但明确禁止 `/search`、`/people/*/collect` 等；未声明的 Crawl-delay 不应理解为可以高频抓取。
- 单 IP 连续抓取数页即可能被临时限流；返回“页面正常但评论为空”是典型现象。

执行边界（若必须爬）：

1. 只抓公开可见的短评，不登录账号批量抓取，不绕过验证码、不伪造高频请求。
2. 单部影片先抓 1—3 页做可行性验证；失败立即停止，不反复重试。
3. 请求间隔 ≥ 3 秒，单次任务总量控制在数千条以内。
4. 记录抓取时间、URL、状态码；在报告中单列“补充数据”，不冒充主数据集。
5. 不抓取用户主页、不做用户画像、不保存可识别个人信息。

**结论：今晚不把爬虫作为主路径；主路径是公开数据集，小批量爬取只用于演示“可扩展性”。**

## 2. 数据理解（第二步）

### 2.1 字段字典（以实际下载为准）

| 字段 | 类型 | 含义 | 质量风险 | 处理动作 |

| Movie_Name_EN | string | 英文片名 | 缺失、译名不一 | 仅展示 |
| Movie_Name_CN | string | 中文片名 | 可能含副标题 | 清洗后作为关联键 |

| Number | int | 评论计数 | 语义需核对 | 仅统计 |

| Date | datetime | 评论时间 | 格式不统一 | 解析为 datetime |
| Star | int | 1—5 星 | 可能缺失/为 0 | 缺失单列，不参与情感聚合 |

### 2.3 文本特性

- 短评以口语化、情绪化、碎片化为主，常见“好看”“烂”“一般”“泪目”“上头”等整体评价，单条信息量低。
- 反讽、反问、网络梗多，词典情感容易误判，例如“真是谢谢导演了”。
- 同一部电影存在大量模板化短评与复制粘贴，尤其热门影片。
- 文本中混有表情符号、颜文字、重复标点、全角字符、繁体字、英文片名。
- 评论常同时涉及多个维度，例如“演技在线，但剧情拖沓”，因此分类必须是多标签。
- 星级与文本情感不完全一致：存在“打五星但吐槽”“打一星但夸演技”的情况。

### 2.4 噪声清单

| 噪声类型 | 例子 | 影响 | 处理 |
|---|---|---|---|
| 广告引流 | “加微信 xxx 拿资源”“高清下载见主页” | 污染词云与分类 | 正则删除 |
| 无信息短评 | “沙发”“打卡”“哈哈哈”“……” | 拉低分类质量 | 长度+规则过滤 |
| 非中文 | 纯英文、日文、数字、表情 | 分词与情感失效 | 中文字符占比过滤 |
| 重复/模板 | 同一文本多人发布 | 虚增热度 | 完全去重 + SimHash 近似去重 |
| 剧透 | “凶手就是……”“最后他们都死了” | 影响阅读体验 | 标记并默认折叠，不直接删除统计 |

## 3. 数据过滤（第三步）

### 3.1 过滤原则

1. **先保真，再保量**：宁可少几百条，也不让广告和模板文本进入词云。
2. **可解释**：每条被删评论必须有 `drop_reason`，便于写报告和复核。
3. **不误杀有效短评**：“好看”“一般”只有 2—3 字，但它是有效整体评价，不能只用长度阈值一刀切。
4. **剧透不删除**：剧透评论对情感统计有价值，只做标记与展示折叠。
5. **顺序固定**：先去重，再去广告，再判语言/长度，最后判相关性，避免规则互相污染。

### 3.2 过滤规则表

| 编号 | 规则 | 判定条件 | 处理 | 预期影响 |
|---|---|---|---|---|
| F1 | 完全重复 | `Comment` 去空白后完全相同 | 保留最早或点赞最高一条 | 降低模板文本 |
| F2 | 近似重复 | SimHash 64 位，汉明距离 ≤ 3 | 保留点赞最高一条 | 去除洗稿/复制 |
| F3 | 同用户同片重复 | 同一 `Username` + 电影，文本高度相似 | 保留最长/最新一条 | 去除刷评 |
| F4 | 广告/水印引流 | 命中 URL、微信号、QQ、加群、资源、私信、公众号、二维码、文本水印、引流后缀等正则 | 删除 | 净化词云 |
| F5 | 联系方式 | 连续 6 位以上数字、邮箱、手机号 | 删除 | 隐私与广告 |
| F6 | 无信息文本 | 去掉标点/表情后中文字符 < 4，且不含情感词 | 删除 | 去除“哈哈哈”“沙发” |
| F7 | 非中文 | 中文字符占比 < 0.5 | 删除 | 保证分词有效；极短有效评价由 F6 单独判断 |
| F8 | 超长短评 | 字符数 > 300 | 截断或转长评表，不进入短评统计 | 控制文本长度 |
| F9 | 想看/标记 | 命中“想看”“标记”“先码”“留着看”且无观后语义 | 删除 | 去除未观影文本 |
| F10 | 纯表情/符号 | 去除表情与标点后为空 | 删除 | 降低噪声 |
| F11 | 剧透 | 命中“剧透/凶手/结局是/最后死/反转是”等 | 标记 `is_spoiler=1`，默认折叠 | 保留统计价值 |
| F12 | 场外体验 | 命中影院、票价、排片、字幕、配音、观众素质 | 保留，标 `is_offtopic=1` | 聚合时可排除 |
| F13 | 星级异常 | `Star` 为空、0、>5 | `star_valid=0`，不参与情感聚合 | 防止均值偏差 |
| F14 | 机器模板 | 相同 8-gram 在 ≥ 20 条评论重复 | 标记 `is_template=1`，默认排除 | 去除水军文本 |

## 4. 数据处理（第四步）

### 4.1 清洗与标准化

按顺序执行：

1. HTML 标签与实体反转义（`&nbsp;`、`<br>`）。
2. 全角转半角，统一标点。
3. 繁体转简体（OpenCC `t2s`）。
4. 去除零宽字符、控制字符、连续重复标点。
5. URL、@用户、话题标签替换为占位符或删除。
6. 表情符号：保留“哭/怒/赞”等少量语义表情为文字标记，其余删除。
7. 英文统一小写；保留片名中的英文。
8. 合并多余空白，去首尾空格。

产出字段：`text_clean`、`char_len`、`zh_ratio`、`emoji_cnt`。

### 4.2 分词与停用词

- 工具：`jieba`，加载自定义词典。
- 自定义词典必须加入：电影名、角色名、演员名、导演名，以及“演技、剧情、节奏、镜头、配乐、特效、反转、烂尾、出戏、代入感、服化道、IMAX”等领域词。
- 停用词：哈工大停用词表 + 百度停用词表 + 自定义补充（“电影”“这部”“感觉”“真的”“比较”等）。
- 词云额外过滤：电影名本身、演员名（避免词云被片名刷屏）、单字、纯数字。
- 产出：`tokens`（空格分隔）、`tokens_nostop`。

### 4.3 情感倾向

采用“双轨”设计，避免把星级和文本情感混为一谈：

| 轨道 | 定义 | 生成方式 | 用途 |
|---|---|---|---|
| `sent_star` | 星级弱标签：1—2 负向、3 中性、4—5 正向 | 直接由 `Star` 映射 | 气泡颜色、整体正面率、稳定可复核 |
| `sent_text` | 文本情感：负向/中性/正向 + 分数 | 情感词典（BosonNLP + 否定词 + 程度副词）为主，SnowNLP 为对照 | 分类别情感、词云分区、与星级交叉验证 |

实现要点：

- 否定词窗口：情感词前 3 个词内出现“不、没、别、无、未、不是”则翻转。
- 程度副词： “非常、特别、太、很、有点、稍微”按权重缩放。
- 分数阈值：总分 > 0.2 为正向，< -0.2 为负向，其余中性；阈值需在 100 条人工标注上校准。
- 反讽检测第一轮不做模型，只在报告中列为误差来源；抽样统计误判率。
- 一致性检验：计算 `sent_star` 与 `sent_text` 的一致率；若低于 65%，以星级为主，文本情感只用于类别内相对比较。

可选增强（有时间再做）：

- 用 `hfl/chinese-roberta-wwm-ext` 在 10 万条星级弱标签上微调 3 分类；按 8:1:1 划分，报告 macro-F1。
- 不作为今晚阻塞项；没有 GPU 就跳过。

### 4.4 评论分类体系

采用 9 类多标签体系，单条最多 3 个标签，必须有一个主标签。

| 编码 | 标签 | 定义 | 典型触发词 | 边界说明 |
|---|---|---|---|---|
| C0 | 整体评价 | 只给总体好坏、推荐/不推荐，不展开具体维度 | 好看、难看、一般、推荐、失望、值回票价 | 若同时有具体维度，C0 可保留但不作主标签 |
| C1 | 剧情叙事 | 故事、剧本、逻辑、节奏、结局、改编、反转 | 剧情、剧本、逻辑、拖沓、烂尾、反转、改编 | “节奏慢”归此；单纯“无聊”若无线索归 C0 |
| C2 | 表演角色 | 演技、演员、选角、人物塑造、台词功底 | 演技、演员、出戏、人物、选角、台词 | 角色颜值讨论也归此 |
| C3 | 视听特效 | 画面、摄影、特效、美术、服化道、镜头 | 画面、特效、摄影、美术、服化道、3D、IMAX | “镜头美”归此；镜头语言风格归 C5 |
| C4 | 音乐音效 | 配乐、主题曲、声音设计 | 配乐、音乐、主题曲、音效、BGM | 歌词内容讨论归 C6 |
| C5 | 导演风格 | 导演、风格、叙事手法、致敬、作者性 | 导演、风格、镜头语言、致敬、氛围 | 导演个人八卦归 C8 |
| C6 | 主题情感 | 立意、价值观、共鸣、感动、治愈、压抑 | 感动、治愈、共鸣、立意、压抑、后劲 | 只写“哭了”且有情绪指向可归此 |
| C7 | 场外体验 | 影院、票价、排片、字幕、配音、观众 | 影院、票价、排片、字幕、配音、观众 | 与影片质量无关，聚合时可切换排除 |
| C8 | 其他/无信息 | 无法归入以上类别、纯情绪符号、无关内容 | 哈哈哈、打卡、路过 | 广告应已被过滤，不应大量落入此列 |

多标签规则：

- 一条评论提到几个维度就打几个标签，最多 3 个；超过 3 个取证据最强的 3 个。
- 主标签 = 文本中篇幅最大、或情感词最集中的维度；纯整体评价的主标签为 C0。
- “演技好但剧情烂” → C2 + C1，主标签取先出现/篇幅更大的维度，并在标注备注中记录。
- 疑问句、比较句按实际评价对象打标；“比第一部好看”归 C0，若提到具体维度则加对应标签。

### 4.5 标注方案

**样本设计**

处理抽样（与 gold 分开）：按电影 × 星级分层，每片每星级至少 50 条、单片上限 1000 条，总数约 2 万；某层不足则全取。固定 `random_state=42`，保存 `sample_ids.csv`，保证全组复现。

- 从过滤后的数据中分层抽样 300 条作为 gold set。
- 分层维度：电影（28 部）× 星级（负/中/正），保证每部、每类都有样本。
- 其中 100 条由两人独立标注，用于计算 Cohen's kappa；其余 200 条一人标注、一人抽查 20%。

**标注表结构**

```csv
comment_id,text,movie,star,c0,c1,c2,c3,c4,c5,c6,c7,c8,primary,sent_gold,is_spoiler,note,annotator
```

**质量控制**

- 先写 1 页标注手册（即 4.4 的定义 + 每类 2 个正例/1 个反例）。
- 预标注 20 条，两人对齐边界后再正式开标。
- kappa 目标 ≥ 0.60；低于 0.60 先讨论修订定义，不直接扩大标注量。
- 争议样本由第三人裁决，记录裁决理由。

### 4.6 分类识别落地

按成本从低到高，今晚至少完成 L0，争取 L1：

| 层级 | 方法 | 输入 | 输出 | 验收 |
|---|---|---|---|---|
| L0 | 关键词/正则规则 | 清洗文本 + 每类 30—50 个种子词 | 多标签 + 主标签 | 在 gold 300 上 coverage ≥ 70%，macro-F1 ≥ 0.45 |
| L1 | TF-IDF 字符 2—4 gram + OneVsRest LinearSVC | gold 300—500 条 | 多标签 + 置信度 | macro-F1 ≥ 0.60；阈值 0.5，低于阈值归 C8 |
| L2 | LLM 零样本/少样本 | 分类定义 + 每类 2 例 + 评论文本 | JSON 多标签 | 在 100 条 gold 上 macro-F1 ≥ 0.65；成本可控才用 |
| L3 | 微调 Chinese-RoBERTa | 1—10 万条弱标签/人工标签 | 多标签 | 作为第二轮，不在作业1阻塞 |

落地策略：

1. 先用 L0 跑全量，得到每类提及率与初步聚合，保证今晚有结果。
2. 用 gold 300 评估 L0；若 macro-F1 不足，优先补种子词与规则，而不是盲目上模型。
3. 若组内有可用 LLM API，用 L2 对 2 万条抽样打标，并用 gold 100 校验；提示词固定温度 0，要求输出 JSON，禁止自由发挥。
4. 若上 L1，优先把 gold 扩到 500 条（300 条基础上补 200 条单标），按 7:3 划分训练/测试；只有 300 条时也可跑通，但报告中必须注明样本量限制。每类都要报 P/R/F1，不只报 accuracy。
5. 全量最终标签 = L0/L1/L2 中验证集表现最好的方案；未达置信度的评论归 C8，不强行分类。

### 4.7 聚合指标（气泡图的数据底座）

以电影为聚合单元，产出 `movie_agg.csv`：

| 指标 | 公式 | 说明 |
|---|---|---|
| `n_valid` | 过滤后评论数 | 气泡大小 |
| `avg_star` | `mean(Star)` | 站内均分（1—5） |
| `star_std` | `std(Star, ddof=1)` | 争议度主指标 |
| `pos_rate` | `count(Star>=4) / n_valid` | 正面率 |
| `neg_rate` | `count(Star<=2) / n_valid` | 负面率 |
| `neutral_rate` | `count(Star==3) / n_valid` | 中性率 |
| `polarization` | `4 * pos_rate * neg_rate` | 两极分化指数，0—1，越高越撕裂 |
| `category_share[c]` | 提及 c 的评论数 / `n_valid` | 评价维度占比 |
| `category_score[c]` | 提及 c 的评论平均星级，按 `(mean_star - 1) / 4 * 100` 映射到 0—100 | 雷达图数值 |
| `category_pos_rate[c]` | 提及 c 且星级 ≥4 的占比 | 类别口碑 |
| `diversity` | `-Σ p_c log(p_c) / log(9)` | 评价维度丰富度，0—1 |
| `top_category` | `argmax(category_share)` | 主评价维度 |
| `top_pos_words` / `top_neg_words` | 类别内 TF-IDF Top 15 | 词云与详情卡 |
| `rep_comments` | 每情感极向按 `Like` 取前 3，长度 10—120，非剧透 | 代表评论 |

分类别聚合另出 `category_agg.csv`：`movie_id, category, mention_cnt, share, avg_star, pos_rate, top_words`。

计算注意事项：

- 气泡大小用 `sqrt(n_valid)` 映射到直径，保证面积与数量成正比。
- `star_std` 与 `polarization` 都保留，图中默认用 `star_std`，tooltip 展示 `polarization`。
- 提及率分母统一用 `n_valid`，不要用“提及总数”，否则各类别不可比。
- 少于 30 条有效评论的电影标记 `low_sample=1`，图中降低不透明度并提示“样本不足”。

### 5.2 气泡图与组合方案映射

**组合方案（明确不使用横向堆叠条、100% 堆叠条、饼图、柱状图）**：

| 层级 | 视图 | 编码 | 作用 |
|---|---|---|---|
| 导航层 | 顶部细长散点气泡 | X=平均星级，Y=星级标准差，大小=评论数，颜色=正面率 | 先选一部电影 |
| 主视图 | 电影 × 类别气泡矩阵 | 横轴 C0—C8，纵轴电影（按星级排序），面积=提及量，颜色=类别正面率 | 看评价维度结构 |
| 流向层 | 类别 → 情感桑基图 | 左节点=9 类，右节点=正/中/负，流宽=提及量 | 看满意/不满意流向 |
| 详情层 | 雷达图 + 词云 + 评论列表 | 六维画像、关键词、原帖 | 验证结论 |

**散点导航映射**：

| 视觉通道 | 变量 | 字段 | 尺度/范围 | 设计说明 |
|---|---|---|---|---|
| X 轴 | 口碑 | `avg_star`（默认）或豆瓣 `rating`（切换） | 1—5 或 0—10 | 默认用样本均分，避免跨源口径不一致 |
| Y 轴 | 争议度 | `star_std` | 0—2 | 越高越两极；中位数处画分割线 |
| 气泡大小 | 讨论热度 | `n_valid` | 直径 12—60 px，面积∝数量 | 用 sqrt 缩放，图例给 3 个参考圆 |

### 5.3 布局与视觉参数

- 布局：顶部细长散点导航（约 20% 高度）— 下方主气泡矩阵（约 50%）— 右侧详情栏（320 px）— 底部桑基/词云联动（约 30%）；左筛选栏 240 px。
- 不使用横向堆叠条、100% 堆叠条、饼图和柱状图；类别构成用气泡矩阵表达，情感流向用桑基表达。
- 画布留白 ≥ 48 px，坐标轴用细线，网格线低对比；不画粗重边框。
- 气泡描边 1 px 白色或深色半透明，选中时 2 px 高亮；重叠用轻量碰撞力（d3-force collision）微调，不改变坐标语义。
- 颜色：连续色带 5 档图例；类型分组用低饱和分类色，避免与情感色冲突。
- 字体：中文无衬线；标题 20—24 px，轴标签 12—13 px，tooltip 12—13 px；正文不小于 12 px（投影可读）。
- 动效：筛选/切换 200—300 ms 过渡；不做无意义弹跳。
- 实现建议：静态原型优先 ECharts（scatter + visualMap + 自定义 tooltip）；需要碰撞微调时用 d3-force 的 collision 力或 ECharts graph 布局；若课程要求原生 SVG，则直接用 D3。28 个气泡不需要 WebGL。

## 6. 关键交互设计

| 编号 | 交互 | 触发 | 反馈 | 验收 |
|---|---|---|---|---|
| I1 | 悬停查看 | 鼠标悬停气泡 | tooltip：片名、均分、评论数、正面率、争议度、Top3 类别 | 200 ms 内出现，不遮挡气泡 |

| I4 | 框选 | 拖拽矩形 | 选中区域内电影，列表与榜单同步 | 显示已选数量，可清除 |
| I5 | 切换编码 | 下拉选择 X/Y/大小/颜色 | 轴与图例更新，禁止同一变量占两个通道 | 切换后不报错、不重叠错乱 |
| I6 | 搜索 | 输入片名 | 模糊匹配，命中气泡高亮并居中 | 支持中文/英文/拼音首字母（可选） |
| I7 | 类别下钻 | 点击雷达轴/热力图单元格 | 评论列表按类别过滤，词云切换为该类别 | 面包屑可返回 |
| I8 | 剧透控制 | 开关“显示剧透” | 默认折叠，开启后展开并标红提示 | 默认不泄露结局 |
| I9 | 联动高亮 | 悬停榜单/列表项 | 对应气泡高亮，反之亦然 | 双向联动无延迟 |
| I10 | 重置 | 点击重置 | 恢复默认视图与筛选 | 状态完全复位 |
| I11 | 矩阵下钻 | 点击矩阵单元格 | 评论列表只显示“该电影 × 该类别”，词云切换 | 面包屑可返回电影/全局 |
| I12 | 桑基流过滤 | 点击某条类别→情感流 | 联动矩阵高亮该类别、列表过滤该情感 | 可再次点击取消 |
| I13 | 手绘稿对照 | 切换“设计稿/成品” | 显示对应手绘草图与当前视图 | 至少 3 组可对照 |

状态与联动规则：

- 只允许一个“主选中”电影；多选通过框选进入“对比模式”，最多 5 部。
- 筛选与选中是两层状态：筛选改变可见集合，选中不改变集合。
- 任何图表点击都写入同一个 `selectedMovieId`，避免各视图各自为政。
- URL 状态可选（`?movie=xxx&genre=剧情`），便于展示时直接打开。

性能与可访问性：

- 28 部电影、每部聚合指标预计算为 JSON，前端无需实时计算。
- 颜色不作为唯一编码，配合大小/标签/tooltip；色带通过对比度检查。
- 键盘可 Tab 聚焦气泡，Enter 选中，Esc 取消。
- 移动端降级为“列表 + 详情”，气泡图横向滚动。

## 附录 A：分类标签判定细则（标注用）

1. 先判断“有没有具体评价对象”，没有则 C0。
2. 有具体对象按对象归类；一条评论可多标，最多 3 个。
3. 主标签取“篇幅最大/情感最强”的对象；并列时取先出现者。
4. “剧情好但演员差” → C1 + C2；主标签按篇幅。
5. “画面很美，剧情一般” → C3 + C1；主标签 C3（若画面描述更多）。
6. “看哭了” → C6；若同时说“因为剧情”则 C6 + C1。
7. “影院太吵，电影还行” → C7 + C0。
8. “比第一部好看” → C0；若提“特效比第一部好” → C0 + C3。
9. 纯“哈哈哈”“打卡” → C8；已在过滤阶段尽量删除。
10. 无法判断 → C8，并在 note 写“语义不明”，不要强行归类。

## 附录 E：可直接改造的最小流水线骨架

这不是最终脚本，只用于今晚先跑通“读取 → 规则过滤 → 规则分类 → 电影聚合”的闭环。先抽 2 万条跑通，再切全量；情感词典、gold 评估和近似去重另行补入。

```python
import re
import pandas as pd

RAW = "work/data/raw/DMSC.csv"
USE = ["Movie_Name_CN", "Username", "Date", "Star", "Comment", "Like"]
df = pd.read_csv(RAW, usecols=USE)
df.columns = ["movie", "user", "date", "star", "text", "like"]
df["text"] = df["text"].fillna("").astype(str).str.strip()
df["char_len"] = df["text"].str.len()
df["zh_ratio"] = df["text"].str.count(r"[\u4e00-\u9fff]") / df["char_len"].clip(lower=1)

AD = r"https?://|www\.|微信|加群|公众号|私信|资源|高清下载|QQ[:：]?\d{5,}"
WANT = r"^(想看|标记|先码|留着看|马克)$"

df["drop_reason"] = ""
df.loc[df["text"].duplicated(keep="first"), "drop_reason"] = "duplicate"
df.loc[df["drop_reason"].eq("") & df["text"].str.contains(AD, regex=True), "drop_reason"] = "ad"
df.loc[df["drop_reason"].eq("") & (df["zh_ratio"] < 0.5), "drop_reason"] = "non_chinese"
SHORT_OK = r"好看|难看|一般|不错|很差|垃圾|无聊|精彩|失望|推荐|喜欢|讨厌|烂片|绝了|神作|催泪"
df.loc[df["drop_reason"].eq("") & (df["char_len"] < 4) & ~df["text"].str.contains(SHORT_OK), "drop_reason"] = "too_short"
df.loc[df["drop_reason"].eq("") & df["text"].str.match(WANT), "drop_reason"] = "want_to_watch"

clean = df[df["drop_reason"].eq("") & df["star"].between(1, 5)].copy()
clean["sent_star"] = pd.cut(clean["star"], bins=[0, 2, 3, 5], labels=["neg", "neu", "pos"])

CATS = {
    "C0": r"好看|难看|一般|推荐|失望|值回票价",
    "C1": r"剧情|剧本|逻辑|拖沓|烂尾|反转|改编|节奏",
    "C2": r"演技|演员|出戏|人物|选角|台词",
    "C3": r"画面|特效|摄影|美术|服化道|3D|IMAX",
    "C4": r"配乐|音乐|主题曲|音效|BGM",
    "C5": r"导演|风格|镜头语言|致敬|氛围",
    "C6": r"感动|治愈|共鸣|立意|压抑|后劲",
    "C7": r"影院|票价|排片|字幕|配音|观众",
}

def label(text):
    hits = [c for c, p in CATS.items() if re.search(p, text, flags=re.I)]
    return ",".join(hits[:3]) if hits else "C8"

clean["labels"] = clean["text"].map(label)
clean["primary"] = clean["labels"].str.split(",").str[0]

agg = clean.groupby("movie").agg(
    n_valid=("text", "size"),
    avg_star=("star", "mean"),
    star_std=("star", "std"),
    pos_rate=("star", lambda s: (s >= 4).mean()),
    neg_rate=("star", lambda s: (s <= 2).mean()),
).reset_index()
agg["polarization"] = 4 * agg["pos_rate"] * agg["neg_rate"]

clean.to_parquet("work/data/interim/comments_labeled.parquet", index=False)
agg.to_csv("work/data/processed/movie_agg.csv", index=False, encoding="utf-8-sig")
print(agg.sort_values("star_std", ascending=False).head(10))
```

运行前确认 `work/data/processed`、`work/data/interim` 已存在；`to_parquet` 需要 `pyarrow`。
